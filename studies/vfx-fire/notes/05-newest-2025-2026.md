# 05 Newest developments (mid-2025 to Nov 2026) for fire and smoke VFX

Researcher angle: what changed this year that matters for a Godot 4 web (WebGL2 Compatibility) top-down pixel-art MMO. Date of research is 2026-11-10. About 29 tool calls. Many secondary sources for 2026 are aggregator sites (cinevva.com, summerengine.com). I flag them where used.

Legend. SHIPPED = in a stable release or a shipped game. RESEARCH = paper, demo or experimental. VIABLE / NOT VIABLE is my judgment for the target stack.

---

## Q1. What changed in Godot 4.5, 4.6, 4.7 and the 4.8 beta for fire and smoke?

### Takeaway
DrawableTexture2D (Godot 4.7, June 2026) is the one change that matters for this study. It is a GPU texture you can blit into with a custom `shader_type texture_blit` shader, which is the clean way to run a DOOM-fire or smoke-advection buffer on the GPU without SubViewport tricks. Its Compatibility (GLES3) support is likely but not stated in the docs, so test a web export before relying on it. No release from 4.5 to the 4.8 beta lists any 2D particle, 2D light or canvas-shader feature. Web export is still WebGL2-only.

### Cited findings
- Godot 4.7 stable shipped 19 June 2026 (secondary source). https://app.cinevva.com/news/2026-06-19-godot-4-7-released , official page https://godotengine.org/releases/4.7/
- The 4.7 release page describes DrawableTexture2D as "a simple API layer" that replaces Viewport workarounds, which it calls "limited and costly". No renderer limits given. https://godotengine.org/releases/4.7/
- DrawableTexture2D API. `setup(w, h, format, fill)`, then `blit_rect(rect, source, modulate, mipmap, material)`. `blit_rect_multi` takes up to 4 sources and 4 targets of equal size and format. Formats are RGBA8, RGBA8 sRGB, RGBAH (16-bit float), RGBAF (32-bit float). Marked experimental. https://docs.godotengine.org/en/latest/classes/class_drawabletexture2d.html
- Blit shaders use `shader_type texture_blit;`, write `COLOR0` to `COLOR3`, read extra inputs via `hint_blit_source1..3`, and support `blend_mix/add/sub/mul/disabled`. Premultiplied alpha is not supported. https://docs.godotengine.org/en/latest/tutorials/rendering/drawable_textures.html
- The implementing PR #105701 added a GLES3 shader file `tex_blit.glsl`, which is the Compatibility backend's code path (seen in a mirror of the merge diff). https://remotebranch.eu/Stowage/godot/commit/fd6e80d4e97ccd4ab4146db018df91c20e07ab4e.diff
- Godot 4.7 web export still uses WebGL 2.0 through Compatibility. No WebGPU. It adds wasm64 export, which lifts the 4 GB memory ceiling (secondary sources). https://app.cinevva.com/news/2026-06-19-godot-4-7-released , https://80.lv/articles/godot-4-7-has-been-released
- 4.7 release page notes that Vulkan Mobile "matches or even outperforms" Compatibility in some benchmarks. No figures. https://godotengine.org/releases/4.7/
- Godot 4.5 (Sept 2025) web change is WebAssembly SIMD. The page says web games "run a bit more smoothly", no number. 4.5 also adds a dedicated 2D navigation server and a stencil buffer described for 3D meshes. https://godotengine.org/releases/4.5/
- 4.5.1 fixed glow intensity not showing in Compatibility (GH-110843). 4.5.2 has "significant crash fixes" for Compatibility. https://godotengine.org/article/maintenance-release-godot-4-5-2/ , https://digitalproduction.com/2025/09/17/godot-4-5-new-buffers-better-access-more-control/
- Godot 4.6 (Jan 2026) release page lists glow blended before tonemapping and rotated scene tiles, nothing for 2D particles or web. https://godotengine.org/releases/4.6/
- 4.6-dev5 reported a 2D renderer rework with GPU-bound 2D scenes "between 1.1× and 7×" faster. The article does not say which renderer. https://digitalproduction.com/2025/12/04/godot-4-6-dev5-lands-d3d12-default-delta-patching-android-gradle-2d-boosts
- Godot 4.8 beta 1 (15 Oct 2026) adds decals to Compatibility (GH-118070). No 2D particle or web items. https://godotengine.org/article/dev-snapshot-godot-4-8-beta-1/
- Web threads. The 4.3 single-threaded export exists because many hosts cannot set the COOP/COEP headers needed for SharedArrayBuffer. It also fixed audio problems on Apple devices. https://godotengine.org/article/progress-report-web-export-in-4-3/
- itch.io has an experimental SharedArrayBuffer checkbox for threaded builds. https://forum.godotengine.org/t/web-export-service-worker-registration-itch-io/105439
- Particles in Compatibility. Godot states both Vulkan and GLES3 support GPU particles. https://godotengine.org/article/progress-report-state-of-particles/ . On web Compatibility, each new GPUParticles2D type causes a lag spike on first use (shader compile). https://forum.godotengine.org/t/handling-particle-shader-compilation-lag-in-godot-4-web-compatibility-renderer/36170 . A 4.1 issue found turbulence dropping Android to about 10 FPS, caused by a collision branch generated even when collision is off. https://github.com/godotengine/godot/issues/83744
- 2D lights. Older reports put the cap at 15 to 16 lights per item per draw call, and 256 per viewport on desktop and 64 on mobile. Nothing from 2025-26 says this changed. https://www.github.com/godotengine/godot/issues/90905 , https://forum.godotengine.org/t/working-around-godots-2d-light-limitations-for-a-dark-game/81311

### Inferences
- DrawableTexture2D replaces the SubViewport ping-pong used in studies #2 and #3. A 320x180 RGBA8 fire buffer is 230 KB. Two buffers ping-ponged with one blit per tick should be trivial on any WebGL2 device. A DOOM fire step, a cooling map and a smoke advection pass all fit in one `texture_blit` shader each. VIABLE on 4.7+ if the GLES3 path works on web. Test it.
- Keep CPU simulation for the authoritative tile fire (server state). Use DrawableTexture2D only for client-side cosmetic buffers.
- Pre-warm every GPUParticles2D material at load (emit one off-screen frame) to hide the first-use shader compile stutter on web. Or use CPUParticles2D for ember and spark puffs, which avoids the compile and is cheap at a few hundred particles.
- Leave turbulence off on web and mobile until it is profiled. Fake drift with a sine on velocity in a custom particle shader.
- Single-threaded web export stays the safe default for an MMO hosted on its own domain only if you cannot set COOP/COEP. On your own server you can set them and use threads. Fire VFX should not depend on threads either way.

### Gaps
- No official statement that DrawableTexture2D works in the Compatibility renderer on web. I did not test.
- I could not confirm whether the 4.6 2D speedup applies to Compatibility.
- No 2025-26 benchmark of threaded vs single-threaded Godot web builds.

## Q2. Which 2025-2026 games have notable pixel-art or systemic fire, and what do devlogs reveal?

### Takeaway
The most useful 2026 reference is Mewgenics (Edmund McMillen and Tyler Glaiel, released Feb 2026). Its tactical fire is a turn-based tile system close to Tibia fire fields. Grass tiles ignite and pass fire to neighbours, burn status deals damage equal to stacks and decays by 1 per turn, and water removes it. Falling-sand games keep appearing (Atomcraft, Stardust Sandbox, Mystic Tesserae, Sandustry) but none of the ones I found published a fire-technique devlog in this window. No Noita successor from Nolla Games has been announced.

### Cited findings
- Mewgenics. Short grass ignites into a fire tile and spreads to adjacent grass. Tall grass and flowers burn and are destroyed. Oil puddles chain-ignite every connected oil tile. Weather modifiers include Wildfire (fire tiles at battle start) and Firestorm (fires become permanent). Community wikis, not developer sources. https://mewgenicswiki.org/tools/elemental-chart , https://mewgenicswiki.org/wiki/weather/wildfire-1 , https://mewgenicswiki.org/wiki/weather/oil-spill-1
- Mewgenics Burn. "Takes {stacks} damage at start of its turn, then decrease Burn by 1." Ignores shields. Stack decay pauses while standing on fire. Removed by water tile, Wet, Freeze or a Remover. Burning units ignite flammable tiles they walk over. https://mewgenicswiki.org/wiki/status-effects/burn
- Tall grass gives up to 50% dodge but one fire flask turns a patch into "a sea of fire". https://mewgenicswiki.org/articles/top-15-mewgenics-beginner-tips
- Atomcraft, falling-sand survival crafting, demo Nov 2025, full release planned early 2026. https://triplejumpgames.itch.io/atomcraft/devlog/1138102/content-update-12-09-2025
- Stardust Sandbox announced a Steam release for Jan 2026. https://starciad.itch.io/stardust-sandbox/devlog
- Sandustry describes every pixel as a physical entity, and flowers that fire ignites to produce resources. No fire devlog found. https://lanttogames.itch.io/sandustry/devlog/891560/demo-hotfix-8-arrives-to-restore-botanical-order
- No Nolla Games successor announcement found. Search results were all about Noita (1.0 on 15 Oct 2020). https://www.pcgamer.com/see-a-world-built-from-physically-simulated-pixels-in-noitas-gorgeous-debut-trailer
- Older but relevant devlogs found during search (pre-2025, flagged by date).
  - Sigil of Kings wildfires (5 Apr 2024). Fire object has about 5 turns of fuel, is inert for the first 3-4, then can ignite neighbours. Tree ignition chance 20% per attempt, higher with more burning neighbours. The first version spread instantly and burned the whole forest. https://byte-arcane.itch.io/sigil-of-kings/devlog/712302/wildfires
  - "Pixel-perfect fire physics" (Sept 2024). CPU grid with temperature, fuel and lifetime per cell. Wood ignites at 300 C, paper 230, oil 210, fabric 250. Heat moves to 4 neighbours. Burnt-out fire becomes smoke at 80% temperature. Packed into a texture (R temperature, G type, B fuel) for a canvas shader. First version ran at 5 FPS and needed chunking, dirty rects and a coarser sim grid. https://bodenmchalewebsite.pages.dev/blog/pixel-perfect-fire-physics.html

### Inferences
- Mewgenics confirms the "stacks minus one per tick" burn model plays well. It maps to Tibia burning conditions with a simpler rule. Good fit for a server-authoritative MMO, since it is deterministic and cheap.
- The "inert for 3-4 ticks, then spreads" delay in Sigil of Kings is a cheap fix for runaway spread. Worth copying for grass tiles.
- The "pack state into a texture, color in a shader" pattern is the right split for Godot. The server sends tile burn state. The client uploads it to a small texture and a canvas shader draws flames.

### Gaps
- No developer-authored Mewgenics fire write-up found. Exact fire-tile duration and spread chance unknown.
- I did not find a 2025-26 top-down pixel RPG devlog that explains fire rendering in depth.

## Q3. Real-time 2D fluid, radiance cascades, WebGPU, and ML fire. What is new and is any of it viable?

### Takeaway
Radiance cascades for 2D glow keep getting refined (Holographic Radiance Cascades, May 2025), but they need many full-screen passes and suit WebGPU or desktop better than WebGL2. WebGPU now ships in Chrome, Edge, Safari 26 and desktop Firefox, but Godot does not export to it, so for this project it is NOT VIABLE until Godot adds a WebGPU backend. ML fire research (FieryGS, ICLR 2026) costs seconds per frame and is NOT VIABLE at runtime. AI sprite tools (PixelLab, Retro Diffusion) are SHIPPED and VIABLE offline for drafting flame and explosion loops, which an artist then cleans up.

### Cited findings
- Holographic Radiance Cascades (arXiv 2505.02041, May 2025) claims results "visually indistinguishable" from a 2D reference at real-time rates. RESEARCH. https://arxiv.org/abs/2505.02041
- A Godot port of the shadertoy radiance cascades exists (radiance-cascades-godot, last updated Aug 2024). Web support not stated. https://relatedrepos.com/gh/Sohojoe/radiance-cascades-godot
- A Unity Asset Store package "Radiance Cascades 2D Global Illumination" exists. SHIPPED as a tool. https://assetstore.unity.com/packages/tools/level-design/radiance-cascades-2d-global-illumination-355802
- GodotFest 2025 talk "Raytracing is simple for 2D games!" by Jaanus Jaggo (Blastronaut) says 2D effects need "quite simple shaders". No numbers or web notes. https://app.media.ccc.de/v/godotfest2025-raytracing-is-simple-for-2d-games/audio
- WebGPU status. Safari 26 on macOS, iOS, iPadOS and visionOS. Firefox 141 on Windows, Firefox 145 on Apple Silicon macOS. Firefox Android, Linux and Intel Mac were still in progress as of late 2025. Chrome Android since 121 (Android 12+). https://web.dev/blog/webgpu-supported-major-browsers , https://www.techspot.com/news/110456-webgpu-now-brings-desktop-quality-graphics-all-major.html
- Godot web export does not support WebGPU, so Forward+ and Mobile cannot run in a browser (secondary, 4.7 coverage). https://app.cinevva.com/news/2026-06-19-godot-4-7-released
- luma.gl has an experimental WebGPU-only dense-grid fire and smoke solver with velocity, pressure, fuel, heat and smoke at fixed 1/60 s steps. RESEARCH/experimental. https://luma.gl/docs/api-reference/experimental/volumetric-fire-simulation
- WebGPU particle fluids in 2025. webgpu-ocean (MLS-MPM) reports about 100,000 particles on integrated graphics and 300,000 on decent GPUs (author-reported). https://awesome.ecosyste.ms/projects/github.com%2Fmatsuoka-601%2Fwebgpu-ocean . Splash (Mar 2025) reported 180k particles on a MacBook Pro. https://redlib.hackliberty.org/r/GraphicsProgramming/comments/1jh3pd2/splash_a_realtime_fluid_simulation_in_browsers/mj4a9em/?context=3
- FieryGS (ICLR 2026) combines Gaussian splatting with volumetric combustion and LLM material reasoning. One summary reports 2.37 s per frame and under 10 GB GPU memory (not confirmed in the paper). RESEARCH. https://iclr.cc/virtual/2026/poster/10006432 , https://www.emergentmind.com/papers/2605.00177
- Retro Diffusion Animation model on Replicate (launched 19 Nov 2025). Generates "low framerate" animated pixel sprites. It has a VFX style at 24-96 px, outputs GIF or spritesheet PNG, and accepts an input palette. SHIPPED, paid per run (price not found). https://replicate.com/blog/retro-diffusions-pixel-art-models-are-now-on-replicate , https://docs.scenario.com/get-started/generation/third-party-model-generation/third-party-model-generation-retro-diffusion
- PixelLab can draft fireballs and spell sheets from prompts like "pulsing flames, trailing embers". The tutorial animates them in other tools (Pix Miniax, Pixelorama). Third-party tutorial summary. https://sozai.app/transcript/make-animated-pixel-art-vfx-pixellab/

### Inferences
- Inference cost. AI generators run on the vendor's servers at authoring time. Runtime cost in the game is zero, because the output is an ordinary sprite sheet. The real cost is cleanup. Expect to fix palette drift, jitter between frames and loop seams by hand.
- A palette-locked AI draft at 32x32 or 48x48 could be a fast start for campfire and torch loops (6-8 frames). It will not beat a procedural DOOM-fire buffer for spreading or interactive fire.
- Radiance cascades are overkill for a 320x180 tile game that already has the Tibia light model from study #5. The cheap win is a block-sum glow (study #2) seeded from fire pixels.
- Stable-fluids smoke at 80x45 or 160x90 is affordable on WebGL2 via DrawableTexture2D ping-pong with a few Jacobi iterations. I did not measure this. For an MMO, sprite puffs with wind drift remain cheaper and easier to sync.

### Gaps
- No Retro Diffusion or PixelLab price per animation found for 2026.
- I found no 2025-26 game that ships radiance cascades for fire glow specifically.
- I did not research neural fluid upsampling (for example tempoGAN successors). Nothing game-ready surfaced in searches.

## Q4. New talks (GDC, GodotCon, etc.) on fire, smoke, stylised or pixel VFX

### Takeaway
The single most relevant new talk is GodotCon Amsterdam 2026 "Procedural Pixel Art: Retro VFX with Shaders" (Julian Rogawski, 23 April 2026). It covers burning sprite effects via UV noise, SubViewport feedback loops and color quantization. No recording link found. GDC 2026 had a smoke booth session (Virtuos) but no main fire talk I could find. Chih-Yu (Geodraws) gave a GDC 2025 VFX Summit talk on stylised torch fire.

### Cited findings
- "Procedural Pixel Art: Retro VFX with Shaders", Julian Rogawski (Nojoule), GodotCon Amsterdam, 23 Apr 2026, 09:25-10:15. Burning, freezing, glitch effects. Techniques are UV manipulation, noise, SubViewport feedback loops and color limiting. https://talks.godotengine.org/godotcon-ams-2026/talk/NSNXFT/
- GDC 2026 booth session "Selling the Illusion: Smoke FX Players Believe", Nick McElmury (Beyond-FX, Virtuos). https://luma.com/zyqqc37d
- Chih-Yu (Geodraws) VFX Summit talk "Math but make it cute" walks through a stylised torch fire. Her page calls it her GDC 2025 talk. https://gdcvault.com/play/1035558/Visual-Effects-Summit-Math-but , https://geodraws.gumroad.com/l/mathbutmakeitcute
- GodotCon Boston 2025 session by Shane Denhardt mentions "reducing frame rate per asset" for a 2D look. https://talks.godotengine.org/godotcon-us-2025/speaker/Y93RDD/
- Ryan Juckett, GDC 2026 "How We Draw a 3D Sprite World" (Never's End). Sprite rendering, not fire. https://www.ryanjuckett.com/how-we-draw-a-3d-sprite-world-gdc2026/
- Unity blog breakdown of Ignitement real-time fluid fire VFX (date not confirmed). https://unity.com/de/blog/real-time-fluid-simulation-fire-vfx-ignitement-breakdown

### Inferences
- Rogawski's SubViewport feedback approach is the pre-4.7 version of what DrawableTexture2D now does. His talk is the closest match to this series and worth watching if a recording appears.
- "Lower frame rate per asset" agrees with study #5's 8-12 Hz flicker. Run flames at 8-12 fps even when the game runs at 60.

### Gaps
- Digital Dragons 2025/2026 programs not checked.
- GDC 2026 VFX Summit full schedule not checked in GDC Vault.

## Q5. Wildfire simulation trends that leaked into games

### Takeaway
I found no clear 2025-26 example of research wildfire models (Rothermel, FARSITE) shipping in a game. Games still use the same simple pattern. A fuel counter per tile, a per-neighbour ignition chance, and an optional wind bias. Mewgenics adds weather presets (Wildfire, Firestorm) as run modifiers, which is a design trend rather than a simulation one.

### Cited findings
- Mewgenics weather modifiers Wildfire and Firestorm. https://mewgenicswiki.org/wiki/weather/wildfire-1 , https://mewgenicswiki.org/wiki/weather/firestorm
- Going Medieval explains why cellular automata fit fire spread, with wind and fuel changing the rate (undated). https://foxyvoxel.io/?p=705

### Inferences
- For an MMO, "weather-as-fire-modifier" is a cheap event hook. A dry-season server event could raise spread chance on grass tiles for an hour.

### Gaps
- Only one search spent here. Wildfire-sim-in-games is under-researched in this note.

## Viability summary for Godot 4 web pixel-art MMO

| Development | Status | Runtime cost | Viable? |
|---|---|---|---|
| DrawableTexture2D GPU buffers (fire, smoke) | SHIPPED 4.7, experimental API | 1 blit per buffer per tick | Likely. Test GLES3 on web first |
| GPUParticles2D in Compatibility | SHIPPED | First-use compile stutter on web | Yes, pre-warm. CPUParticles2D for small counts |
| Particle turbulence | SHIPPED | Reported 10 FPS on Android (4.1) | Avoid on web/mobile |
| WebAssembly SIMD web export | SHIPPED 4.5 | Small speedup, no number | Yes, free |
| wasm64 web export | SHIPPED 4.7 | n/a | Not needed at 320x180 |
| WebGPU in Godot | Not shipped | n/a | No |
| Radiance cascades 2D glow | RESEARCH / addons | Many full-screen passes | No, use block-sum glow |
| WebGPU fluid solvers | Experimental demos | Compute shaders | No (WebGL2 target) |
| FieryGS, neural fire | RESEARCH | About 2.37 s/frame (reported) | No |
| PixelLab, Retro Diffusion VFX loops | SHIPPED tools | Zero at runtime, vendor cost at authoring | Yes, offline drafts with manual cleanup |
| Mewgenics-style burn stacks | SHIPPED game | Integer per unit per tick | Yes, ideal for server |
