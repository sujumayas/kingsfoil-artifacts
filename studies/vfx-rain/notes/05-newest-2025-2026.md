# 05 — Newest developments (mid-2025 → 2026-11-08) for rain / wetness / puddles / ripples
Angle: what is new and usable for a web-first Godot 4 top-down pixel game (Compatibility/WebGL2).
Researcher notes, compiled 2026-11-08. ~34 tool calls. Cited = from a URL; Inference = mine.

---

## Q1. Godot 4.7: DrawableTexture2D (wetness / ripple / puddle maps)

**Takeaway:** This is the single most relevant new engine feature. DrawableTexture2D shipped in **Godot 4.7 (stable, June 2026)**. It is a GPU texture you "blit" into with a custom `shader_type texture_blit` shader. It **is implemented in the Compatibility (GLES3/WebGL2) driver**, so it should work on web. It replaces the old "SubViewport as paint canvas" hack for wetness masks, footprint maps, puddle-depth maps, and ripple-height fields. The API is still marked **experimental**.

**Cited findings**
- Release: 4.7 stable announced around 2026-06-19 (news [cinevva 2026-06-19](https://app.cinevva.com/news/2026-06-19-godot-4-7-released)); CG Channel covered it on 2026-06-23 ([cgchannel](https://www.cgchannel.com/?p=176830)). The official release page describes it as "a simple API layer that abstracts away all the technical noise", replacing "hacky Viewport solutions" and RenderingDevice ([godotengine.org/releases/4.7](https://godotengine.org/releases/4.7/)). `version.py` on the `4.7-stable` tag reads `status = "stable"` ([raw](https://raw.githubusercontent.com/godotengine/godot/4.7-stable/version.py)).
- Implementation PR #105701 "Implement DrawableTextures" was merged **2026-01-30** ([PR](https://github.com/godotengine/godot/pull/105701)). Follow-ups:
  - resize fix #118243, merged 2026-04-14
  - experimental-flag docs #120092, merged 2026-06-09
  - still open: #118272 `blend_rect()`, #115655 DrawableTextureLayered (texture arrays), #119929 max-size checks
  (all found via GitHub search API, links `github.com/godotengine/godot/pull/<n>`).
- API from the class XML ([DrawableTexture2D.xml @4.7-stable](https://raw.githubusercontent.com/godotengine/godot/4.7-stable/doc/classes/DrawableTexture2D.xml)):
  - `setup(width, height, format, color=white, use_mipmaps=false)` must be called first.
  - `blit_rect(rect: Rect2i, source: Texture2D, modulate, mipmap, material)` takes a ShaderMaterial with a TextureBlit shader.
  - `blit_rect_multi(rect, sources[≤4], extra_targets[≤3], ...)` writes up to **4 sources → 4 targets (MRT)**, and missing sources become black.
  - `generate_mipmaps()`.
  - Formats: `RGBA8`, `RGBA8_SRGB`, `RGBAH` (RGBA16F), `RGBAF` (RGBA32F).
  - `setup`, `blit_rect` and `blit_rect_multi` are flagged `experimental=""`.
- Compatibility support: `drivers/gles3/storage/texture_storage.cpp` at 4.7-stable has `texture_drawable_initialize` and `texture_drawable_blit_rect`. It also contains a default `shader_type texture_blit;` with `source_texture0..3 : hint_blit_source0..3` and a `blit()` function, a dedicated FBO plus quad VAO, and size limits of 1..16383 px. All output targets must be the same size ([gles3 texture_storage.cpp](https://raw.githubusercontent.com/godotengine/godot/4.7-stable/drivers/gles3/storage/texture_storage.cpp)).

**Inferences (not verified by running)**
- **Rain wetness map:** one RGBA8 DrawableTexture at 1 texel per tile or per 2–4 px.
  - Channels: R = wetness, G = puddle water depth, B = mud, A = footprint age.
  - Each rain tick, blit a full-rect "wet += rate × exposure" pass with the shelter mask as `source_texture1`.
  - Stamp footprints with small `blit_rect` calls.
  - The world shader reads the map to darken or saturate the palette. This is the same design as snow-depth (#1) and acid-film (#2), now done on the GPU.
- **Ripple sim (wave equation) on WebGL2:** needs the previous two states.
  - The API copies *from* a source *to* the target, so reading a texture while writing it is a GL feedback loop.
  - Use 2–3 DrawableTextures and swap them (ping-pong), or use `blit_rect_multi` to write state + velocity at once.
  - Not confirmed whether a texture may be passed as its own source. **Test it.**
- **RGBAH/RGBAF on WebGL2:** rendering to float targets needs `EXT_color_buffer_float`. RGBA8 is the safe web choice: pack the height as 8-bit around 0.5, which is enough for pixel-art ripples.
- **Experimental status:** the API may change in 4.8, so wrap it behind your own small class.

**Gaps:** No public benchmark of DrawableTexture on web. No official 2D demo or tutorial found (the tutorials list in the XML is empty). The 4.7 release page lists it under 3D-ish workflow (CG Channel puts it under "3D").

## Q2. Godot web (Compatibility) limits that shape rain VFX (4.4–4.7)

**Takeaway:** On web you get the Compatibility renderer only. Its limits:
- GPUParticles2D works, but **no particle trails, no SDF collision, no compute, no RenderingDevice, no HDR 2D**.
- Screen texture **is** supported, so puddle-reflection or distortion via `SCREEN_TEXTURE` / `hint_screen_texture` is fine.
- Plan splash-on-impact without collision: use a lifetime-based splash, a shader ripple field, or CPU-side spawning.

**Cited findings** ([renderers.rst, godot-docs master](https://raw.githubusercontent.com/godotengine/godot-docs/master/tutorials/rendering/renderers.rst); rendered: [docs](https://docs.godotengine.org/en/stable/tutorials/rendering/renderers.html)):
- Web platform: Compatibility ✔, Mobile ✘, Forward+ ✘.
- Compatibility: Screen texture ✔, Depth texture ✔, Compute shaders ✘, Particle trails ✘, Particle SDF collision ✘, 2D HDR viewport ✘, RenderingDevice access ✘.
- Colour precision is RGBA8 (LDR, medium).
- GodotCon Amsterdam 2026 (2026-04-23) talk "Procedural Pixel Art: Retro VFX with Shaders" by Julian Rogawski (Nojoule). It covers UV/noise, **feedback loops using SubViewport**, retro colour quantisation, and GPU performance ([talk](https://talks.godotengine.org/godotcon-ams-2026/talk/NSNXFT/)). SubViewport feedback is the pre-4.7 way to do ripple sims and is still valid.

**Inferences**
- **Rain streaks:** a cheap, web-safe option is a single full-screen canvas_item shader (world-anchored hash grid), which is what Weather FX Free does (Q4). Alternatives are GPUParticles2D without collision, or CPUParticles2D when you need per-drop logic (e.g., fire hits).
- **Splash-at-ground in top-down view:** the "ground" is the drop's own landing point, so spawn the splash at end of life (particle sub-emitter "at end", or a shader ring field). Collision isn't needed. This makes the Compatibility collision gap mostly irrelevant for top-down.
- **2D lights + normal maps** (CanvasTexture normal) work in Compatibility in 4.x. A wet sheen can be done by boosting specular/shininess via the CanvasTexture specular channel. *Not re-verified here; see the doc on 2D lights.*

**Gaps:** No checks for 4.4–4.6 specific 2D particle changes. No measured WebGL2 particle budgets.

## Q3. WebGPU in browsers and Godot web

**Takeaway:** WebGPU shipped in all major browsers by late 2025, though not on Linux and with Android limits. **Godot's official web export is still WebGL2 / Compatibility only.** The only Godot-WebGPU path is a **third-party experimental** RenderingDeviceDriver (David Walter, "Godot WebGPU" / Shiny Gen), presented at GodotCon Boston 2026. Don't plan on it for production.

**Cited findings**
- web.dev, 2025-11-25 ([web.dev](https://web.dev/blog/webgpu-supported-major-browsers)):
  - Chrome desktop since 113 (Windows D3D12, macOS, ChromeOS; Linux in progress).
  - Chrome Android since 121, needing Android 12+ and Qualcomm/ARM GPUs.
  - Firefox 141 on Windows; Firefox 145 on macOS Tahoe 26 ARM64 only; Linux/Android in progress.
  - Safari on macOS/iOS/iPadOS/visionOS 26.
- GodotCon Boston 2026, 2026-07-21, talk "Godot WebGPU (Shiny Gen Engine)" by David Walter ([talk](https://talks.godotengine.org/godotcon-boston-2026/talk/CT739D/)):
  - Experimental backend built as a RenderingDeviceDriver; the abstract claims it runs Forward Mobile and Forward+ in Chrome, Firefox and Safari.
  - Translates SPIR-V→WGSL.
  - Claims "~4x WebGL" and "~70% of native" (**self-reported**).
  - No official schedule. Repo: [github.com/dwalter/godotwebgpu](https://github.com/dwalter/godotwebgpu).

**Inference:** For this project, design every rain technique to run on WebGL2 / Compatibility (RGBA8, no compute). Treat compute-based ripple sims as a desktop-only bonus.

**Gaps:** Couldn't fetch the repo README (GitHub API blocked for this repo in the session). No Godot core-team statement on WebGPU found in this pass.

## Q4. Community assets (last ~18 months) — shaders, addons, packs

**Takeaway:** There are a few genuinely useful, permissively licensed 2D options. The best direct fit:
- **Weather FX Free** (CC BY 4.0, 2026-09): single-shader rain with ground splashes, pixel-art mode, tested on Compatibility/web.
- **Rain Drop (floor effect)** shader (CC0/MIT, 2025-08): world-anchored hashed-cell ring ripples with a pseudo-normal for screen distortion. This is the canonical "rain rings on ground" trick.
- **Puddle System** addon (MIT, 2026-08): 2D noise puddles, reflections, ripples, footsteps.

Several popular "rain puddle" shaders are 3D/SSR and don't apply.

- **Hand-animation recipe (BudgetPixel, 2026-08-12)** ([budgetpixel](https://budgetpixel.com/blog/how-to-animate-pixel-art-rain-and-reflections-in-4-frames)):
  - **4-frame loop**; 10–15 one-px streaks at a **2:1 slope**, moving **4–6 px per frame** and wrapping at a new X.
  - Splash: F1 2-px line → F2 4-px hollow ring → F3 two outward dots → F4 erased.
  - Puddle shimmer: shift the puddle's pixel rows ±1 px on frames 2 and 4.
  - Directly codeable as a palette-index shader.
- Godot Asset **Store** (store.godotengine.org) also lists Weather FX Free ([store](https://store.godotengine.org/asset/heyheythere/weather-fx-free/)). The store overhaul came with 4.7 ([alternativeto](https://alternativeto.net/news/2026/6/godot-4-7-adds-arealight3d-asset-store-overhaul-gabe-support-and-hdr-output/)).

**Inferences**
- A world-anchored hashed-cell ring field, as in Rain Drop (floor), is the go-to stateless puddle-ripple method:
  - O(25 cells) per pixel; can drop to a 3×3 loop for low-res.
  - Scale ring count by rain intensity: per-cell "active" probability = intensity.
  - Quantise the ring to 1 px and 2 palette steps to keep it pixel-art.
- Mask it with the DrawableTexture puddle map (Q1) so rings appear only where water stands.

**Gaps:** itch licences and dates are unverified. No 2D GitHub ripple-sim repos (WebGL2 ping-pong) from 2025–26 were found in this pass.

## Q5. Games 2025–2026 with notable rain/weather (and technique details)

**Takeaway:** Big 2025 AAA weather tech is mostly about clouds, wind and character wetness, not puddles. It is useful only as concepts:
- **Ghost of Yōtei**: wetness splatted into a directional grid around characters.
- **Borderlands 4** (GDC 2026): a surface-weather render pass and artist-authored forecasts.

Pixel/indie titles praised for rain in this window are thin. **rain98** (2026 demo) is praised for rainy-night atmosphere. No technique devlogs were found for Octopath Traveler 0 or Silksong rain.

**Cited findings**
- **Ghost of Yōtei** (PS5, launched 2025-10-02; PlayStation tech deep dive dated 2025-10-23) ([PS Blog](https://blog.playstation.com/?p=411201)):
  - "Characters are made wet, bloody, muddy, or snowy by splatting data into a directional grid around them."
  - Wind drives grass, cloth and tassels.
  - Cloud speed is raised for stormy weather; cloud shadow map → god rays.
  - Snow deformation via displacement buffer.
  - No rain or puddle specifics given.
  - Art director's quote: "the trees know how strong the wind is" ([GamesRadar](https://www.gamesradar.com/games/open-world/ghost-of-yoteis-art-director-wanted-the-rpg-to-look-like-a-living-painting-but-the-detail-required-stresses-even-me-out-when-the-wind-blows-the-trees-know-how-strong-the-wind-is)).
- **Borderlands 4** weather (UE5). GDC talk, 2026-03-13, by Brian McNett (Gearbox): artist-directed "forecasts" emulating climates, localised forecasts per region, a custom render pass applying weather to surfaces, and optimising global dynamic material effects. Framed as useful "even without dynamic weather" ([GDC schedule](https://schedule.gdconf.com/session/the-dynamic-weather-systems-of-borderlands-4-how-they-can-apply-to-games-without-dynamic-weather/917367)).
- **Death Stranding 2** (PS5, 2025-06-26): the pre-release graphics analysis (GamingBolt, 2025-03-13) only mentions rain in passing. It highlights a gradually building dust storm with particles and volumetrics, plus lightning ([GamingBolt](https://gamingbolt.com/death-stranding-2-on-the-beach-graphical-analysis-a-new-dawn-for-decima)). Timefall specifics were not found.
- **rain98** (C#4R4CT3R; Steam demo; full release "next year" = 2027), preview dated 2026-10-16 ([GamingTrend](https://gamingtrend.com/previews/rain98-so-far-is-a-masterclass-in-atmosphere/)):
  - Mixed first-person, isometric and pixel scenes.
  - Street lamps reflect in puddles; a window vibrates with the rain.
  - Blue palette, binaural rain audio, film grain.
  - Shows how much of rain's "feel" comes from audio, palette and a rattling window rather than drop counts.
- **Octopath Traveler 0** (HD-2D): release date **2025-12-04**, announced at the Nintendo Partner Direct on 2025-07-31 ([Game Informer](https://gameinformer.com/nintendo-partner-direct/2025/07/31/octopath-traveler-0-is-coming-this-december), [OneMoreGame](https://onemoregame.ph/2025/07/octopath-traveler-0-coming-december-4/)). No rain-technique sources found.
- **Hollow Knight: Silksong** (2025-09-04): searched for rain. Bilewater is a swamp area ([wiki](https://hollowknight.wiki/w/Bilewater); Team Cherry on Bilewater: [GamesRadar](https://www.gamesradar.com/games/action/team-cherry-finally-answers-to-the-crimes-of-silksongs-bilewater-we-just-love-a-big-swamp-we-wanted-some-kind-of-poison-status-for-ages)). No rain-tech source; **unverified** whether any area has notable rain.
- **Witchbrook** (Chucklefish, top-down pixel life sim): delayed again. Game Informer reported a January release date on 2026-10-28 ([GI](https://gameinformer.com/2026/10/28/cozy-magical-sim-witchbrook-gets-a-january-release-date); PC Gamer reported a 2027 delay: [PCG](https://www.pcgamer.com/games/rpg/witchbrook-is-delayed-again-now-set-for-release-in-2027/)). Not yet released, so no shipped weather to study.
- **Mina the Hollower** (Yacht Club, 8-bit-style top-down) is out per [Digital Citizen](https://www.digitalcitizen.life/mina-the-hollower-is-now-out-on-xbox-pc-playstation-and-switch-after-beating-forza-horizon-6-on-metacritic/) (release date not extracted). Rain usage is unverified.

**Inferences**
- Yōtei's "directional grid around characters" maps neatly to pixel art:
  - Give each character a tiny 4-direction wetness vector (N/E/S/W, 0–255 each).
  - Wind-facing side wets faster.
  - Sprite shader darkens the palette by side.
  - Dries at a rate set by shelter and sun.
  - Cheap and readable.
- Borderlands' "forecast" idea fits an MMO: per-region scripted weather sequences (drizzle → storm → clearing mist) authored as data and synced server-side, instead of random weather per client.

**Gaps:**
- Kingdom Come: Deliverance II (Feb 2025, before the window), Mafia: The Old Country (Aug 2025), Dune: Awakening (Jun 2025, sandstorms) and Hades II 1.0 (Sep 2025) were not researched in this pass.
- Stardew 1.6 "Green Rain" is March 2024, outside the window.
- No pixel-art 2025–26 devlog with concrete rain numbers was found.

## Shipped vs experimental (summary)
- **Shipped and usable on web now:**
  - canvas_item shaders with SCREEN_TEXTURE
  - GPUParticles2D (no trails or collision) and CPUParticles2D
  - SubViewport feedback
  - DrawableTexture2D (4.7 stable, but the API is marked *experimental*)
  - Weather FX Free (CC BY)
  - Rain Drop floor shader (CC0/MIT)
  - Puddle System (MIT)
- **Experimental / not for production:** Godot WebGPU backend (third party); DrawableTextureLayered and `blend_rect` (open PRs).
- **Browser-level:** WebGPU shipped (Nov 2025 status), but Godot doesn't use it officially.
