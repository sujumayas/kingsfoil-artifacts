# 05 — Newest developments (mid-2025 → 2026-11-09): forests / trees / foliage / birds in pixel-art, top-down, Godot & web

Researcher angle: what is NEW and SHIPPED (vs experimental) that matters for study #4 (Trees/Forests).
About 35 tool calls. Some sources (godotengine.org dev-snapshot articles, GitHub API) were blocked; mirrors are noted.

## Q1. 2025–2026 pixel / top-down games praised for forests, trees and seasons. Release dates checked.

### Takeaway
Few new top-down pixel games from this period have published technical devlogs on trees. The verified ones mostly give **date checks** and **art-constraint lessons**. The clearest recent constraint document is Mina the Hollower's: GBC-like limits, 4 colours per 8x8 sprite tile, a 64-colour palette and 256x144. It is a good model for palette-limited forests. The two big cozy-sim forest games (Witchbrook, Haunted Chocolatier) are **still unreleased**.

**Mina the Hollower art rules** (Yacht Club blog, first published 2022 as a Kickstarter update; the post says its images are no longer representative): https://www.yachtclubgames.com/blog/the-art-of-the-game
- 256x144 widescreen; GBC was 160x144.
- Custom **64-colour palette** arranged as gradients.
- Sprites: **4 colours per 8x8 tile**, including black and transparency, so sprites are usually 2 visible colours. Extra colours are allowed when a part is split along the grid.
- Background tiles use **cool, earthy, real-world tones**. Saturated colour is **reserved for sprites and interactive objects**. Directly relevant: keep forest tiles desaturated so birds, fruit and pickups pop.
- Rules broken on purpose: 60 fps, parallax, simulated per-row "H-interrupt" scanline effects for background VFX, and limited sprite scale/rotate. No anti-aliasing shaders and no 3D.

### Inferences
- The Mina rule set (desaturated environment, saturated interactables, per-tile colour limits) maps neatly onto a palette-indexed forest: trees in 3–4 ramp entries, interactables kept out of those ramps.
- Witchbrook (2027) and Haunted Chocolatier (TBA) cannot be cited as shipped references for seasonal forests yet. For seasonal trees, Stardew Valley remains the shipped benchmark.

### Gaps (not verified in this pass; do not cite without checking)
- Stardew 1.6 tree changes (Mystic Tree, green-rain moss), Coral Island and Sun Haven seasonal trees, and Hollow Knight Silksong (believed Sept 2025), Hades II 1.0 (believed Sept 2025) and Octopath Traveler 0 (believed Dec 2025): I did not fetch sources for these. None is top-down pixel with documented tree tech.
- I found no 2025–26 devlog that specifically covers **birds** in a top-down pixel game.

## Q2. Godot 4.4 → 4.7: 2D-relevant engine changes

### Takeaway
For a web-first 2D forest, the important shipped items are:
- **4.4 (Mar 2025): 2D instance uniforms in CanvasItem shaders, without breaking batching.** This gives per-tree sway phase, season offset or tint at zero extra draw calls. It is the main enabler for "one material, many varied trees."
- **4.4: 2D batching extended** from Compatibility to Forward+ and Mobile.
- **4.5 (Sept 2025):** TileMapLayer **chunked physics** (merged collision shapes), a dedicated **NavigationServer2D**, and **WASM SIMD** for web exports.
- **4.6 (Jan 2026):** a 2D renderer rework that lowers the GPU cost of batching. Secondary reports give 1.1x–7x in GPU-bound cases, "especially on older devices". Rotatable scene tiles.
- **4.7 (19 Jun 2026):** **DrawableTexture2D** (draw into a texture without a Viewport), **2D Scene Paint Mode** (off-grid scattering of scenes in the editor), and GradientTexture2D `FILL_CONIC`.
- **Web is still WebGL2 / Compatibility in 4.7. No WebGPU.**

### Cited findings
- **4.4**, from https://godotengine.org/releases/4.4/
  - "2D batching" (PR #92797, Stuart Carnie): batching previously existed only in Compatibility and now covers the other backends too.
  - **2D shader instance uniforms** (PR #99230): per-instance uniform values in CanvasItem shaders. The page says this "does not break batching".
  - Compatibility fallback when Vulkan/D3D12/Metal is missing (PR #97142).
  - 2D physics interpolation arrived earlier, in **4.3**.
- **4.5**, from https://godotengine.org/releases/4.5/ (release ≈ 15–16 Sept 2025 per https://www.cgchannel.com/?p=170196; 4.5.2 builds dated 19 Mar 2026)
  - TileMapLayer physics merges cell shapes into larger collision shapes instead of one body per tile (Gilles Roudière).
  - Dedicated NavigationServer2D, so pure-2D exports no longer need 3D navigation.
  - Web: WASM SIMD on automatically. The page says it "isn't a fix" for unoptimised games.
- Related RD-renderer PR #104566, "2d: Use dynamic buffers for instance data": on UMA devices the instance data is written once instead of twice. A test with 20,000 textured 1x1 rects that still batch went from **3161 to 3487 fps (~10%)**. Applies to the RD canvas renderer, not Compatibility. https://github.com/godotengine/godot/pull/104566 (merge version not confirmed; GitHub API blocked).
- **4.6** (released late Jan 2026, per https://digitalproduction.com/2026/01/28/godot-4-6-arrives-with-major-cg-friendly-updates/)
  - dev5 (Dec 2025): "the GPU cost of batching has been reworked", with a reported **1.1x–7x speedup in GPU-bound scenarios**. https://digitalproduction.com/2025/12/04/godot-4-6-dev5-lands-d3d12-default-delta-patching-android-gradle-2d-boosts
  - GameFromScratch's wording: "rewrite of the 2D renderer… especially on older devices". https://gamefromscratch.com/godot-4-6-dev5-and-dev6-released/
  - The PR number and the exact renderer were not confirmed; the official dev-snapshot page was blocked.
  - Official 4.6 2D section: **rotatable scene tiles** in 90° steps (PR #108010). https://godotengine.org/releases/4.6/
  - Third-party claim, **unverified and from a vendor**: "15-20% fewer draw calls in typical 2D scenes" from their internal tests. The same article says 2D GPU particles need Forward+, which looks wrong (inference: Compatibility has had GPUParticles2D since 4.2). https://www.strayspark.studio/blog/godot-46-rendering-deep-dive-ssr-lightmapper-performance
- **4.7** (stable **19 Jun 2026**, per https://app.cinevva.com/news/2026-06-19-godot-4-7-released). From https://godotengine.org/releases/4.7/:
  - **DrawableTexture2D** (PR #105701, Colin O'Rourke): an API for drawing directly on textures. It replaces the Viewport or RenderingDevice workarounds.
  - **2D Scene Paint Mode** (PR #109360, shortcut `B`): scatters scenes such as decorations off-grid. Editor-only.
  - GradientTexture2D `FILL_CONIC` (PR #115394).
  - No y-sort, 2D light or 2D shadow changes are listed.
  - Web: still **WebGL 2 through Compatibility, no WebGPU**. New: **wasm64** exports, which lift the 4 GB memory cap. The article corrected an earlier claim that WebGPU had shipped behind a flag.

### Inferences (for the study)
- **Per-tree variation for free:** declare `instance uniform float sway_phase; instance uniform float season_t; instance uniform int variant;` in one shared CanvasItem shader. Each tree stays in the same batch as long as texture and material are shared, which means one atlas. This is the 2025+ "correct" way. It replaces the older trick of encoding a seed into `modulate`.
  - **To verify:** do instance uniforms work in the **Compatibility** renderer? The 4.4 notes don't restrict them, but I didn't confirm it.
- **DrawableTexture2D** suits a low-res, world-aligned **shade / canopy-coverage map**: 1 texel per tile, with trees stamped into it when chunks load, then sampled by the ground and character shaders for "standing in shade". Other uses: a **trample/brush map** (grass bent where the player walked) and a **snow-on-canopy accumulation map**, reusing the snow study's depth-byte idea. Before 4.7 this needed a SubViewport.
- **Scene Paint Mode** speeds up hand-placing forest decoration (stumps, mushrooms, fallen logs) without a scatter plugin. It is editor-only, so runtime procedural forests still need code.
- A 4.6 GPU-batching gain is plausible for low-end mobile, but **it applies to RD renderers**. Web/Compatibility had batching already, so there will likely be less change there. Measure it.

### Gaps
- I found no published 2D sprite-count benchmarks for **web or mobile** on 4.5–4.7. The only number is the 20k-rect desktop test above.
- The 4.6 dev5 PR number and author are unconfirmed.
- No y-sort changes were found for 4.4–4.7.

## Q3. Community assets from the last ~18 months: shaders, plugins, generators, packs

### Takeaway
- **Best new shader:** "2D Pixel perfect wind & sway effect" (CC0, June 2026). It **snaps** the wind offset to the sprite's pixel grid, so canopies don't smear sub-pixel, and it is atlas-safe via `REGION_RECT`.
- **Occlusion / see-through:** no dedicated new 2D shader was found. The 2025–26 forum answers are per-tile `TileData.modulate` runtime updates or scene tiles.
- **Procedural tree generators** are maturing: the Gentree Aseprite extension (v1.0–1.3, early 2026) and the MIT "Procedural Pixel Art Tree" Godot `@tool` (Apr 2026).

### Cited findings: shaders (godotshaders.com)
- **2D Pixel perfect wind & sway effect**, by kaeylos. Published **25 Jun 2026**, modified 6 Nov 2026. **CC0** (code only; page images/videos excluded). https://godotshaders.com/shader/2d-pixel-perfect-wind-sway-effect/
  - Method: scale `VERTEX` by `margin_scale` (1–4) to leave room to bend.
  - Convert UV to region-local space via `REGION_RECT`.
  - Quantise: `floor(local_uv*region_px)/region_px`.
  - Sample 2D gradient noise scrolled by `TIME*wind_speed`, masked by height and divided by region width in px.
  - Add `sin(TIME*sway_speed)` weighted by height.
  - Clamp to the region rect so atlas neighbours don't bleed.
  - Defaults: wind_strength 1.0, wind_scale 10, wind_speed 0.1, sway_strength 0.5, sway_speed 0.5.
  - The page notes that the `REGION_RECT` exposure came with PR #90436 in **Godot 4.5**.
- **2D Wind Sway / Tree & Grass Motion Shader (v2)**, by Purga. Published **26 Nov 2025**. **CC0**. https://godotshaders.com/shader/2d-wind-sway-tree-grass-motion-shader-2/
  - Sine sway that grows toward the top of the sprite, with a smoothstep mask and edge-alpha fade.
  - **No instance uniforms**, so all trees sharing the material sway in phase. My inference: add an instance uniform phase.
- Tag page with the older and popular 2D options, e.g. "2D wind sway" (GLES3, the most used) and "Wind sway for foliage and flags": https://godotshaders.com/shader-tag/tree/ . **None of the shaders on the tree tag is a 2D occlusion / see-through shader.**

### Cited findings: occlusion (top-down, Godot)
- **May 2025** thread: for single-tile trees, use `_use_tile_data_runtime_update()` / `_tile_data_runtime_update()` to change one tile's `TileData.modulate.a`, fading only the tree near the player. https://forum.godotengine.org/t/make-a-wall-tree-a-little-bit-translucent-trasnparent-when-there-is-a-player-behind-it-in-2d-top-down-especially/111322
- **Feb 2026** thread: suggested approach is scene-collection tiles, each tree a scene with its own fade script. https://forum.godotengine.org/t/tilemap-layers-transparency-when-player-behind/133218

### Cited findings: generators and plugins
- **Procedural Pixel Art Tree**, by Desarrh. v1.0.0, **10 Apr 2026**, **MIT**, Godot 4.3+. https://godotengine.org/asset-library/asset/5021 ; repo https://github.com/Desarrh/Procedural-Tree-Godot
  - A single `@tool` script with no dependencies.
  - Builds trees from leaf blobs and canopy shapes, with a 3-colour trunk shade, light rays, hue shift, foliage outline and sway.
  - Also produces bushes, corals, crystals and cacti.
- **Gentree** (Aseprite extension), by devkidd. v1.0.0, then updates **7 Feb → 10 Mar 2026** (v1.3.0). https://devkidd.itch.io/gentree/devlog/1351052/gentree-v100 ; https://community.aseprite.org/t/extension-gentree-procedural-tree-generator-for-aseprite/27983
  - Recursive branches: trunk height, fork frequency, branch levels.
  - Leaf density, cluster size and type (round/triangle), shade variation, outlines, shadow-direction flip.
  - **Forest Mode** fills a rectangle with several trees.
  - Seasons are not built in. Licence and price are not on the devlog page.
- Other itch tools to evaluate, not fetched: https://4b3c.itch.io/procedural-pixel-art-tree-generator , https://wubs.itch.io/pixeltrees , https://heosphorus.itch.io/tree-factory , https://nofacer.itch.io/pixotree
- **Scatter for big forests (3D, for context only):** Proton Scatter and Spatial Gardener are the addons recommended in a **Jul 2026** thread on "thousands of trees" in 4.7. That thread is 3D: MultiMesh per chunk / visibility range, alpha scissor. https://forum.godotengine.org/t/best-approach-for-rendering-a-procedurally-generated-forest-with-thousands-of-trees-in-godot-4-7/141770

### Cited findings: pixel tree asset packs (seasonal)
- **Growable Trees**, by Seliel the Shaper. https://seliel-the-shaper.itch.io/growable-trees
  - Birch, maple and chestnut, each with **4 growth stages**. The final stage has top and stump split for chopping.
  - **6 seasonal variants**: spring, summer, autumn, autumn bare, winter bare, winter bare + snow.
  - **80x96 px** cells, with and without a semi-transparent shadow.
  - $7.99. **Licence not stated on the page; check before use.**
- **HUSHED VALE – Trees & Bushes**, by dsatpxls. https://dsatpxls.itch.io/hushed-vale-trees-bushes/devlog
  - Willow trees, 18 variants (Mar 2025); desert trees (Mar 2025); **autumn recolour (5 Sept 2025)**; pale trees (16 Sept 2025).
  - Licence not stated on the devlog page.
- **Green Heart base pack**, 16x16, "Seasonal Winds V2.0" update adds winter/spring/summer/fall decorations. Undated; licence not shown. https://helm3t.itch.io/green-heart-base-pixel-asset-pack/devlog/958829/seasonal-winds-v20-season-update

### Inferences
- Packs consistently use **6 seasonal states**, with the bare and snow variants split, plus **separate shadow sprites**. That matches a "palette-swap leaves + separate trunk/shadow layers" design.
- Pixel-snapped noise wind plus instance-uniform phase is the current best-practice combination for "alive" canopies that stay crisp.

### Gaps
- No dedicated 2D seasonal-palette tool was found.
- Licences for most itch packs are not on the pages fetched. Check each pack's store page or bundled licence file.

## Q5. AI / ML pixel-art tree generation: what is real in 2025–26

### Takeaway
The tools are real and commercial: PixelLab, Retro Diffusion, Scenario, Ludo and others. PixelLab and Retro Diffusion document tileset workflows. But **no tool guarantees pixel-consistent output**. Using AI art also has a measurable **reputational cost on Steam**. For a palette-locked, hand-authored tree set, AI is at most a sketch or ideation aid. Manual cleanup and palette quantisation are still required.

### Cited findings
- Cinevva comparison guide (published 4 Sept 2026, updated 8 Nov 2026; **Cinevva sells its own image tool**, so treat as vendor-adjacent). https://app.cinevva.com/guides/ai-pixel-art-generators
  - **PixelLab:** tileset workflows, 4- and 8-direction views, skeleton animation, which "does not guarantee consistent pixels". Commercial use of output is allowed; training other models on the output needs permission.
  - **Retro Diffusion:** Aseprite extension at $65 full / $20 Lite, which the developer says is being phased out for a native editor. Metered cloud API. Local output can be used commercially; the cloud has separate terms.
  - **Scenario:** Starter $15/mo, Pro $45/mo with custom training. Does not guarantee uniqueness or copyright protection.
  - The guide declares **no quality winner** and advises testing tile edges and atlas layout yourself.
  - Retro Diffusion itch pages: https://astropulse.itch.io/retrodiffusion
- **Steam AI disclosure:** **49.9%** of October 2026 releases carried an AI disclosure, up from 26.4% in October 2025. Games with ≥50 reviews averaged **77% positive with a disclosure vs 83% without**. These are community data (Reddit user ploz), and the article says the review gap doesn't prove causation. https://powerupgaming.co.uk/2026/11/02/almost-half-of-steams-october-releases-disclosed-ai-use/

### Inferences
- For tree **variety**, procedural generation in our own style (Gentree, Desarrh's generator, or a custom canvas demo) plus palette swaps gives consistency, zero licence risk and no Steam AI disclosure.
- If AI is used at all, keep it to concept thumbnails that are redrawn. Generated pixels shipped in the game trigger the disclosure.

### Gaps
- I found no independent, same-prompt benchmark of AI tileset seam quality.

## Q6. Recent talks: GDC / GodotCon / GodotFest 2025–2026

### Cited findings
- **GodotCon Amsterdam 2026, 23 Apr:** "Procedural Pixel Art: Retro VFX with Shaders", Julian Rogawski (Nojoule). https://talks.godotengine.org/godotcon-ams-2026/talk/NSNXFT/
  - Covers UV manipulation and noise, **SubViewport feedback loops**, retro colour limiting and quantisation, and GPU performance. Pitched as an alternative to hand-drawn frames or gen-AI.
  - Directly relevant to palette-quantised canopy effects and to burnt or dead forest.
- **GodotCon Amsterdam 2026, 24 Apr:** "The long road to a million trees", Bart Wilmink. https://talks.godotengine.org/godotcon-ams-2026/talk/DL7SJJ/
  - Renders **200k–800k trees per frame** in stock Godot, adapting Witcher 4-style voxel LOD.
  - Covers MultiMesh LOD limits, worker threads, extending ProtonScatter, and MMI buffer streaming for fast startup.
  - **3D and experimental.** Lesson for us: chunked buffers streamed over time.
- **GodotFest 2025, 11 Nov 2025:** "Plants, Polygons and Pixels: Large-Scale Vegetation Rendering in Godot", Karl Bittner (45 min). https://media.ccc.de/v/godotfest2025-plants-polygons-and-pixels-large-scale-vegetation-rendering-in-godot
  - 3D: EZTree/Blender pipelines, photo billboards, scattering driven by geodata, LOD and impostors.
- **GodotFest 2025:** "Raytracing is simple for 2D games!", Jaanus Jaggo (Blastronaut). https://app.media.ccc.de/v/godotfest2025-raytracing-is-simple-for-2d-games/audio
  - 2D ray-traced lighting with simple shaders. A possible route to dappled canopy light, though costly on web.
- **GodotFest 2025:** "Tilemaps" talk (not fetched). https://app.media.ccc.de/v/godotfest2025-tilemaps
- **GDC 2026:** "How We Draw a 3D Sprite World", Ryan Juckett (Never's End). Slides were posted 8 Jun 2026; the page itself doesn't describe tree techniques. https://www.ryanjuckett.com/how-we-draw-a-3d-sprite-world-gdc2026/
- **GDC 2026:** "The Modular and Expressive World Art of Keeper" (not fetched; 3D). https://schedule.gdconf.com/session/the-modular-and-expressive-world-art-of-keeper/915052

## Shipped vs experimental (summary)
| Item | Status |
|---|---|
| 2D instance uniforms (4.4), 2D batching on all backends (4.4) | Shipped |
| TileMapLayer chunked physics, NavigationServer2D, WASM SIMD (4.5) | Shipped |
| 2D batching GPU-cost rework (4.6) | Shipped; numbers are second-hand |
| DrawableTexture2D, Scene Paint Mode, wasm64 (4.7) | Shipped (Jun 2026) |
| WebGPU in Godot web export | **Not shipped** as of 4.7 |
| WebGPU in browsers | Shipped in Chrome, Edge, Safari 26 and Firefox (Windows); gaps on Linux and Android |
