# 05 — Newest developments (mid-2025 → 2026-11-08) relevant to top-down pixel snow in Godot / web

Researcher angle: what is NEW (engine features, web platform, community assets, talks, games) that changes how we'd build snow for a web-first Godot 4 top-down pixel game (Asterion Online etc.).
Date of research: 2026-11-08. Tool budget used: ~40 calls (slightly over the 25–35 guideline).

---

## Q1. Godot engine features 4.5 → 4.7 that matter for snow

### Takeaway
- **The biggest new thing for snow is `DrawableTexture2D` + `texture_blit` shaders (Godot 4.7, 19 Jun 2026).** It is a first-class, GPU-side "paint into a texture" API, and it **is implemented in the GLES3/Compatibility renderer**, so it works on the web. That is the clean primitive for a persistent **snow-depth / footprint / trail map** (stamp a footprint texture with `blend_sub`, stamp "snowfall" with `blend_add`, run a full-rect custom blit for melt/refill). Before 4.7 the same thing needed a `SubViewport` with `render_target_clear_mode = NEVER` ping-pong hacks (users report trouble keeping past frames — see forum thread below).
- **On web you are on the Compatibility renderer: no compute shaders, no particle trails, no particle SDF collision** (the feature GPUParticles2D uses to collide with `LightOccluder2D`). So "flakes land on roofs/walls via GPU particle collision" is **not web-viable**; do landing/accumulation in a texture/CA instead.
- 4.5 and 4.6 brought nothing snow-specific in 2D; useful side items: WebAssembly SIMD on by default for web (4.5), TileMapLayer chunked physics (4.5), shader baker (4.5, desktop/console load-time), wasm64 web builds (4.7, lifts 4 GB limit).
- **WebGPU in Godot: still NOT shipped** in 4.7. Only an experimental third-party backend exists (David Walter, GodotCon Boston 2026).

### Cited findings
- **Godot 4.7 stable released June 19, 2026** (a week after RC2). Web export still WebGL 2.0 via Compatibility; added wasm64; "Godot doesn't support WebGPU yet" (article was corrected after wrongly claiming a WebGPU flag). https://app.cinevva.com/news/2026-06-19-godot-4-7-released (secondary source; CG Channel 23 Jun 2026 confirms DrawableTexture2D "new API layer that lets you paint directly onto a texture": https://www.cgchannel.com/?p=176830)
- **DrawableTexture** landed via **GH-105701 by Colin O'Rourke (ColinSORourke)**, announced in "Dev snapshot: Godot 4.7 beta 1", **24 April 2026**, as a "simple API layer" for drawing on a texture directly. https://godotengine.org/article/dev-snapshot-godot-4-7-beta-1/
- **API (class reference, master)** — https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/DrawableTexture2D.xml and https://docs.godotengine.org/en/latest/classes/class_drawabletexture2d.html
  - `setup(width, height, format, color=WHITE, use_mipmaps=false)` — **marked experimental**.
  - `blit_rect(rect: Rect2i, source: Texture2D, modulate=WHITE, mipmap=0, material=null)` — experimental.
  - `blit_rect_multi(rect, sources[≤4], extra_targets[≤3 DrawableTexture2D], modulate, mipmap, material)` — writes up to 4 outputs (COLOR0..COLOR3) in one pass — experimental.
  - `generate_mipmaps()`, `set_format()`, `set_use_mipmaps()`.
  - Formats: `RGBA8`, `RGBA8_SRGB`, `RGBAH` (RGBA16F), `RGBAF` (RGBA32F).
  - `BlitMaterial.blend_mode`: MIX, ADD, SUB, MUL, DISABLED, PREMULTIPLIED_ALPHA (enum) — https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/BlitMaterial.xml
- **Tutorial "Using DrawableTextures"** (docs master): default `shader_type texture_blit;` with `void blit(){ COLOR0 = texture(source_texture0, UV) * MODULATE; ...}`; render modes `blend_mix/add/sub/mul/disabled`; premultiplied alpha *not* supported in shader render_mode; **`modulate = Color(0,0,1,0)` writes only the blue channel** (channel masking → pack several snow fields into one RGBA texture). Material is passed per call, so "multiple types of draws to the same texture" are easy. https://raw.githubusercontent.com/godotengine/godot-docs/master/tutorials/rendering/drawable_textures.rst
- **Compatibility (web) support verified in source**: `drivers/gles3/storage/texture_storage.cpp` contains `_tex_blit_shader_initialize()` with the default texture_blit shader, FBO and quad setup. https://raw.githubusercontent.com/godotengine/godot/master/drivers/gles3/storage/texture_storage.cpp (lines ~321–403 at time of check)
- **Renderer feature table (Godot 4.7 docs)**: web → "Compatibility is the only choice"; Compatibility: Compute shaders ❌, Particle trails ❌, **Particle SDF collision ❌**, 2D HDR viewport ❌, RenderingDevice access ❌, colour precision RGBA8. https://docs.godotengine.org/en/4.7/tutorials/rendering/renderers.html
- Related forum Q: GPUParticles2D rigid/hide collisions need a LightOccluder2D (that is the 2D SDF path). https://forum.godotengine.org/t/why-do-gpuparticles2d-collisions-rigid-hide-need-an-lightoccluder-to-work/64814
- **Godot 4.5** (released mid-Sept 2025; CG Channel article 16 Sep 2025 https://www.cgchannel.com/?p=170196): **WebAssembly SIMD enabled by default** for web; shader baker (up to 20× faster load on Metal/D3D12 in TPS demo — vendor/Godot-reported); stencil buffer (3D); **TileMapLayer chunk physics** merging cell shapes. https://godotengine.org/releases/4.5/
- **Godot 4.6** (released ~26–27 Jan 2026; CG Channel 27 Jan 2026 https://www.cgchannel.com/?p=173665): glow before tonemapping, AgX controls, D3D12 default on Windows, scene instances on tile grid rotatable in 90° steps; nothing 2D-particle/snow-specific in release page. https://godotengine.org/releases/4.6/
- **4.7 particles**: "Fix angular velocity" (breaking, GH-117861), "scale 3D and rotation 3D in particle process" (GH-112447), "Fix particles moving when timescale is 0" (GH-109911); Polygon2D fast path (GH-117334). https://godotengine.org/article/dev-snapshot-godot-4-7-beta-1/
- Pre-4.7 pain point (SubViewport accumulation): Godot forum, 17 Aug 2025, Godot 4.4, 3D snow via ortho camera → SubViewport heightmap; author "can't seem to get it to keep past frames" for accumulation; unanswered. https://forum.godotengine.org/t/interactive-snow-shader-issues/119668

### Inferences (mine)
- Suggested snow map with DrawableTexture2D (web-OK): one RGBA8 texture at **1 texel per tile or 2–4 texels per tile** (e.g. 256×256 for a 64×64-tile area at 4 texels/tile). Channels: R = snow depth, G = "trampled/compacted", B = wetness/slush, A = shelter/exposure mask (baked once from roof/tree/wall tiles). Footprint = `blit_rect` small 4×4 stamp with SUB on R + ADD on G; snowfall/melt = one full-rect custom `texture_blit` per N frames (reads exposure in A, sun mask). This is a GPU cellular automaton exactly in the DOOM-fire spirit. Needs ping-pong (two DrawableTexture2Ds via `blit_rect_multi`'s `extra_targets`) if the blit shader must read its own previous state — **unverified whether a texture_blit can sample its own target**; check before relying on it.
- Because RGBA8 is 8-bit, slow melt rates (<1/255 per step) need stochastic/dithered decrements or stepping every N frames — this actually helps the pixel look (edges melt first, ragged).
- APIs are flagged `experimental` → expect signature changes in 4.8; wrap in one small script.
- Fallback for <4.7 or CPU-authoritative gameplay (MMO server needs snow depth for slowdown): CPU byte array per tile + `Image.set_pixel`/`set_data` → `ImageTexture.update()` only on dirty chunks. (No new 2025–26 perf data on `Image.set_pixel` found.)

## Q2. Web platform: WebGPU / WebGL2 in 2025–2026

### Takeaway
WebGPU is now on by default in Chrome/Edge (Win/mac/ChromeOS, Android 12+ ARM/Qualcomm), Firefox 141+ (Windows) and 147+ (all macOS), and Safari 26 (macOS/iOS/iPadOS/visionOS). **Linux and Firefox-Android remain partial.** But **Godot can't use it** (no WebGPU backend in core as of 4.7), so a Godot web game must still target **WebGL2 + Compatibility renderer**. Design snow for fragment shaders + render-to-texture, not compute.

### Cited findings
- web.dev, **25 Nov 2025**: "WebGPU is now supported in major browsers" — Chrome/Edge from 113 (Android 121+, Android 12+, Qualcomm/ARM GPUs); Firefox 141 Windows, 145 macOS Tahoe ARM64; Safari 26. Linux "in progress". https://web.dev/blog/webgpu-supported-major-browsers
- gpuweb implementation-status wiki (**last edited 2 Oct 2026**): Chrome Linux shipped on Intel Gen12+ since 144, NVIDIA/Wayland since 147, others behind flag; Windows ARM64 behind flag; Firefox macOS all versions since 147, Linux Nightly only ("expects to ship on Linux in 2026"), Android behind flag; Safari 26 all Apple platforms. https://github.com/gpuweb/gpuweb/wiki/implementation-status
- GodotCon Boston 2026 talk **"Godot WebGPU (Shiny Gen Engine)"**, David Walter, **21 Jul 2026**: experimental WebGPU `RenderingDeviceDriver` running Forward Mobile/Forward+ in Chrome/Firefox/Safari; claims **~4× faster than Godot's WebGL pipeline and ~70% native speed** (speaker-reported, not independently verified); challenges SPIR-V→WGSL, WASM↔JS call overhead, no push constants/subpasses. Repo: https://github.com/dwalter/godotwebgpu ; talk: https://talks.godotengine.org/godotcon-boston-2026/talk/CT739D/
- Godot 4.7: web still WebGL 2.0; wasm64 added. https://app.cinevva.com/news/2026-06-19-godot-4-7-released

### Inferences
- For a web-first MMO, budget for WebGL2 lowest common denominator through 2027. A WebGPU path (compute-based snow sim) is a "nice later" only if Godot core adopts it.

### Gaps
- No official Godot roadmap statement on WebGPU found in this session.

## Q4. Recent games (2025–2026) praised for snow/winter; techniques from devlogs

### Takeaway
I found **no 2025–26 pixel-art/HD-2D title with a published technical breakdown of snow**. Square Enix HD-2D coverage (Octopath Traveler 0, Dec 2025; DQ I&II HD-2D, Oct 2025) talks about lighting/palette/diorama staging, not weather. The best directly transferable published technique remains **Slime Rancher 2's top-down interaction render texture (2023)**. Recent winter indies emphasise mechanics (shovelling, persistent footprints, cold meters) over published rendering methods.

### Cited findings
- HD-2D (The Verge feature, late 2025): lighting 2D sprites in Unreal as in a 3D scene; Hayasaka: palette, effects and camera determine "atmosphere"; overusing a colour range flattens depth. No weather discussion. https://scour.ing/@tyler/p/https://www.theverge.com/entertainment/840080/square-enix-hd2d-games-octopath-dragon-quest
- **Slime Rancher 2 (Monomi Park), Game Developer, 27 Apr 2023**, Edward del Villar: top-down RGBA render texture with signed values (R ground/snow, G grass, B water ripples, A extra grass pushdown); actors spawn particles drawn additively into it; "one draw call per interaction type"; buffer follows player, snapped to world-space step to avoid jitter, fades with distance; snow-topper meshes vertex-offset (pushed down in trail, raised at edges); static "snow-occlusion" quads keep snow pushed down near objects; inspired by Uncharted 4 SIGGRAPH 2016. No resolution/perf numbers, no refill details. https://www.gamedeveloper.com/design/slime-rancher-2-snow-particle-effects
- Winter-themed 2026 releases (The Verge via pulse.bot, **9 May 2026**): *Moomintroll: Winter's Warmth* (hand-drawn) and *Froggy Hates Snow* (roguelike, cold survival) — "shoveling, persistent footprints, snowball fights", "dynamic snow physics"; no rendering detail. https://www.pulse.bot/gaming/news/let-it-snow-294bc3d1-0efb-4003-bdf0-c57d774a513a/
- *Winter Burrow* (Noodlecake, 2025): cold meter; **screen ices over** as warning to return home. https://aftermath.site/winter-burrow-demo.md
- Itch pixel snow tile packs updated 2025 (e.g. Pixel Crawler – Snow Tiles devlog https://anokolisa.itch.io/free-pixel-art-asset-pack-topdown-tileset-rpg-16x16-sprites/devlog/901218/pixel-crawler-snow-tiles) — art reference only.

### Inferences
- "Screen frost vignette when cold" (Winter Burrow) is a cheap, readable UI-level snow cue worth listing as a technique.
- For "Games that used it" in the final study, Slime Rancher 2 is the strongest documented case for interaction maps; older pixel games (Stardew, Eastward, etc.) will need to come from other researchers' notes.

## Q6. ML / neural approaches

### Takeaway
Recent work is about **3D Gaussian-splat / 4D scene weather** (offline or heavy real-time on desktop GPUs). **Not viable or appropriate for palette-limited pixel art on WebGL2.** The GodotCon 2026 pixel-VFX talk explicitly positions handcrafted shader algorithms as the alternative to generative AI.

### Cited findings
- "Let it Snow! Animating 3D Gaussian Scenes with Dynamic Weather Effects via Physics-Guided Score Distillation", arXiv 2504.05296 (Apr 2025). https://arxiv.org/abs/2504.05296
- "Weather-Magician: Reconstruction and Rendering Framework for 4D Weather Synthesis In Real Time", arXiv 2505.19919 (May 2025). https://arxiv.org/abs/2505.19919v1
- Non-ML but recent: "Hybrid Weather Simulation System for Real-Time Rendering" (CESCG 2026). https://cescg.org/wp-content/uploads/2026/04/Aszyk-Hybrid-Weather-Simulation-System-for-Real-Time-Rendering-1.pdf (not read)

### Inference
- Only plausible ML use: offline asset help (generating snow-variant tiles) — artist-validated taste rules argue against it; out of scope for runtime.

## Summary of what's new and actionable
1. **Godot 4.7 `DrawableTexture2D` + `texture_blit` (Jun 2026, experimental, works on Compatibility/web)** → the go-to primitive for snow depth/footprint/melt maps; channel masking via `modulate`; up to 4 MRT outputs.
2. **Web = Compatibility = no compute, no particle collision, no trails** → flakes "landing" must be faked (texture CA / spawn-at-random-exposed-cell), not GPU collision.
3. **WebGPU is broadly available in browsers (Nov 2025+) but not in Godot core**; only an experimental fork.
4. **Community assets cover only falling snow** (CC0 Multilayer shader 2025; CC BY Weather FX Free with pixel mode, 2026; MIT WeatherSystem2D 2026). Accumulation/interaction/time in 2D remain uncovered.
5. Talks: GodotCon AMS 2026 pixel VFX with SubViewport feedback loops + palette quantisation; atmosphere/weather-state talk.
