# 05 — Newest developments (mid-2025 → 2026-11-08) for ACID / goo / corrosion / slime VFX

Researcher angle: what is NEW (released/announced games, Godot 4.4–4.7 features, community assets, talks) that matters for a top-down pixel-art acid system in Godot 4 (web-first, Compatibility/WebGL2).
Date of research: 2026-11-08. ~36 tool calls.

---

## Q1. Recent games (2025–2026) with notable acid/goo/slime/corrosion systems

### Takeaway
The flagship 2025 "goo hazard" is **Hollow Knight: Silksong's maggot water (Bilewater / Putrified Ducts)** — notable not for damage but for a *resource-drain status* (silk drain + heal block) with a clear cure verb (Bind) and a counter-item (Wreath of Purity) that was buffed in a patch after player outcry. That is a design lesson more than a rendering one. No other 2025–26 headline release surfaced a spectacular acid/corrosion system in my searches; the strongest *technical* novelty is in falling-sand games and Godot tooling (Q2/Q3).

### Cited findings
- **Silksong — Bilewater / Putrified Ducts.** Wiki: the Ducts hold "vile and disgusting water, filled with Muckmaggots"; Citadel waste "poisoned Bilewater". https://hollowknight.wiki/w/Putrified_Ducts
  - Status mechanics (guide site, not official): silk **drains over time**, **healing is blocked**, no direct HP damage; screen edges "pulse green" and maggots crawl across the Silk bar UI; **cure = Bind**, which purges maggots instead of healing. https://xboxplay.games/hollow-knight-silksong/how-to-cure-poison-from-maggot-water-in-hollow-knight-silksong-67004 (article names the area "Sinner's Rise" — likely an error; treat area attribution with caution.)

### Inferences
- Silksong's maggot water is a good template for **"acid as a status that attacks a resource, not HP"**: e.g., acid on gear = durability drain, acid on player = regen block; with (a) diegetic UI corruption (maggots on bar → our version: green bubbles eating the durability pips), (b) a cure verb, (c) a counter-item. Lesson from Patch 4: punishing goo areas need generous counters or players hate the area.
- Pixel-art acid inspirations in 2025–26 are mostly in **falling-sand** titles (Sandustry, Sand Slide, Powdered World Engine), whose rules transfer to a top-down tile grid if "down" is replaced by "downhill" on a height/slope map.

- Did not find a 2025–26 roguelike with notable *item corrosion*; searched only lightly.

## Q2. Godot 4.4–4.7 features that matter

### Takeaway
**DrawableTexture2D (Godot 4.7)** is the single most important new feature: a GPU-side, persistent paint target with custom `texture_blit` shaders, **implemented in the Compatibility (GLES3) driver**, so it should work on web. It replaces SubViewport ping-pong hacks for acid stain maps, wet maps, corrosion masks and cellular-automaton liquid. Caveats: methods flagged **experimental**; Compatibility is RGBA8 for color precision; float formats on WebGL2 need checking.

### Cited findings — DrawableTexture2D
- Release: Godot 4.7 stable announced ~2026-06-19/23 (news: https://app.cinevva.com/news/2026-06-19-godot-4-7-released , https://digitalproduction.com/2026/06/23/godot-4-7-turns-up-hdr/ ). Release page: DrawableTexture2D "replaces the earlier workarounds" via Viewport or RenderingDevice. https://godotengine.org/releases/4.7/
- Implementation PR **#105701 "Implement DrawableTextures"**, merged/closed **2026-01-30**; follow-up fixes #118243 (resize, 2026-04-14), #118535 (removed non-functional set_width/height), #121054 (remove clamping in linear_to_srgb, 2026-07-15). https://github.com/godotengine/godot/pull/105701
- API (class XML, master): https://raw.githubusercontent.com/godotengine/godot/master/doc/classes/DrawableTexture2D.xml
  - `setup(width, height, format, color=WHITE, use_mipmaps=false)` (experimental)
  - `blit_rect(rect: Rect2i, source: Texture2D, modulate=WHITE, mipmap=0, material=null)` (experimental)
  - `blit_rect_multi(rect, sources[≤4], extra_targets[≤3], modulate, mipmap, material)` — up to 4 inputs / 4 outputs (MRT). Missing sources → black.
  - Formats: `RGBA8`, `RGBA8_SRGB`, `RGBAH` (RGBA16F), `RGBAF` (RGBA32F).
- `texture_blit` shader type: single `blit()` function; render modes `blend_disabled` (default per reference page), `blend_mix`, `blend_add`, `blend_sub`, `blend_mul`; **no premultiplied alpha**; inputs `hint_blit_source0..3`, outputs `COLOR0..3`, built-ins `UV`, `FRAGCOORD`, `MODULATE`, `TIME`. https://github.com/godotengine/godot-docs/blob/master/tutorials/shaders/shader_reference/texture_blit_shader.rst
  - Note inconsistency: tutorial says default blit shader uses `blend_mix`; reference table says `blend_disabled` is default. https://github.com/godotengine/godot-docs/blob/master/tutorials/rendering/drawable_textures.rst
  - Material passed per call (not bound to resource) → many draw types on one texture; `BlitMaterial.blend_mode` overrides. Same tutorial.
- **Compatibility support (source-level evidence):** `drivers/gles3/storage/texture_storage.cpp` contains `_tex_blit_shader_initialize()` with the default texture_blit shader, FBO and quad buffers. https://github.com/godotengine/godot/blob/master/drivers/gles3/storage/texture_storage.cpp

### Cited findings — other renderer facts (Compatibility = web)
- Compatibility color precision **RGBA8**; **particle trails ❌**, **particle SDF collision ❌**, **2D HDR viewport ❌**, **RenderingDevice ❌**, **compute ❌**. https://github.com/godotengine/godot-docs/blob/master/tutorials/rendering/renderers.rst
- Canvas-shader 2D SDF: `texture_sdf`, `texture_sdf_normal`, `sdf_to_screen_uv`, `screen_uv_to_sdf`; SDF generated from LightOccluder2D with "SDF Collision" on (default). https://github.com/godotengine/godot-docs/blob/master/tutorials/shaders/shader_reference/canvas_item_shader.rst — The GLES3 canvas shader defines `texture_sdf()` and the GLES3 canvas rasterizer binds an SDF texture → appears supported in Compatibility (source: https://github.com/godotengine/godot/blob/master/drivers/gles3/shaders/canvas.glsl , https://github.com/godotengine/godot/blob/master/drivers/gles3/rasterizer_canvas_gles3.cpp ).
- 4.7 other 2D bits: Scene Paint Mode (2D scatter brush), `GradientTexture2D` FILL_CONIC, one-way collision any direction. https://godotengine.org/releases/4.7/
- Experimental **WebGPU backend** (GodotCon Boston 2026, David Walter, 2026-07-21): RenderingDeviceDriver for browser, ~**4x faster than WebGL pipeline**, ~**70% of native** (speaker-reported). Not upstream/shipped. https://talks.godotengine.org/godotcon-boston-2026/talk/CT739D/

### Inferences
- Use DrawableTexture2D as a **world-space acid layer** at tile×N resolution (e.g., 1 texel per pixel of a 512×512 region): R = acid amount, G = flow velocity/age, B = stain/etch, A = corrosion progress. Splat with `blit_rect` + circle texture; tick a CA/flow `texture_blit` pass via ping-pong between two DrawableTexture2Ds (see Q3 ProfesorShader shader). Read in the floor `canvas_item` shader for palette-quantized rendering.
- Stick to **RGBA8** on web: WebGL2 float render targets need `EXT_color_buffer_float` (my knowledge, not verified here); 8-bit is enough for palette-index style acid (DOOM-fire-like).
- Gameplay readback (does this tile hurt?) should stay **CPU-side** on a coarse tile grid; GPU texture is for visuals. Reading back GPU textures each frame is costly (inference; not measured).
- `texture_sdf` gives "distance to walls" in canvas shaders → cheap acid meniscus/edge-hugging stains and fume fade near walls — only if walls have LightOccluder2D.
- GPUParticles2D on Compatibility: no trails, no SDF collision → for bubbles/fizz use short-lived CPUParticles2D or shader-only bubbles (inference).

### Gaps
- No measured cost of DrawableTexture2D blits on WebGL2 / mobile; no confirmation of RGBAH/RGBAF on web.
- CanvasGroup metaball (threshold) approach: found only old references (captainproton42 2D Metaballs, ericl521/godot-metaball; GitHub API blocked). No new 2025–26 canonical asset verified. https://captainproton42.github.io/2DMetaballs/
- Did not verify Image/ImageTexture.update performance changes in 4.4–4.7.

## Q3. Community assets (last ~18 months)

### Takeaway
Two finds are directly reusable: **ProfesorShader's "Dynamic Animated Liquid Texture" (CC0, 2026-04-12)** — a DrawableTexture2D wet-map flow sim with concrete params — and **Sand Slide's acid element (MIT)** — a dead-simple probabilistic CA with acid gas, dilution, base neutralization and per-material acid resistance. Together they cover the "acid spreads + eats + fumes + neutralizes" loop.

### Cited findings
- **Dynamic Animated Liquid Texture (Blood, Paint, Water and other Fluids)** — ProfesorShader, posted **2026-04-12**, **CC0** code. Two `texture_blit` shaders + **three DrawableTexture2Ds**: two ping-pong a wet map (R = liquid amount, G = flow velocity), third = albedo. Physics: each texel compares height (noise height map × `height_mult`) to neighbors; liquid/velocity flow downhill weighted by slope; `velocity_keep = 0.998`/step; color = `smoothstep(mask_min, mask_max, amount)` mixing background/liquid colors; `texel_size = 1/512` in sample. https://godotshaders.com/?p=15449
- **Goo** — dairycultist, 2025-06-02, MIT, *spatial* (3D) refraction goo via normal rotation + screen-texture offset. Not directly pixel-2D. https://godotshaders.com/shader/goo/
- **Goop Projectile** — Erich_L, 2023-08-07, MIT, canvas_item, Godot 3.5: scrolling noise flow map offsets UVs, two-color blend by noise. Older than window but trivially portable. https://godotshaders.com/shader/goop-projectile/
- **Sand Slide** (kiwijuice56, MIT, C++ GDExtension, UI in Godot 4.6). Each element implements `get_acid_resistance()` ∈ [0,1], `get_toxicity()`. README: https://github.com/kiwijuice56/sand-slide/blob/main/README.md ; licence: https://github.com/kiwijuice56/sand-slide/blob/main/LICENSE.md
  - **Acid** (id 21) constants: `DECAY_AIR=1/512` (if touching air → acid gas), `DECAY=1/2048`, `EVAPORATE=1/64` (on fire → gas), `EAT=1/16`, `EMIT=1/64` (gas puff), `DOWN=1/1.2`, `DOWN_BLOCK=1/16`, `MIX=1/2` (touch water → acid water), cold → frozen acid. Eat rule: move into neighbor with probability `EAT × (1 − neighbor.acid_resistance)`; vacated cell becomes gas with p=EMIT else empty. Touching **Base** (id 136) with p=MIX → becomes **water**. Acid's own acid_resistance = 1.0, density 64. https://github.com/kiwijuice56/sand-slide/blob/main/extension/elements/chemical/acid.h
  - **Acid water** (diluted, id 59): same EAT 1/16 but `MIX=1/4`, `DECAY_AIR=1/256`, fluidity 1 vs acid's 2; on fire → gas or vapor 50/50. https://github.com/kiwijuice56/sand-slide/blob/main/extension/elements/chemical/acid_water.h
  - **Acid gas** (id 22): `DECAY=1/160` per tick, random walk sideways/up, density 32, **toxicity=1** (`is_poisoned` checks 8 neighbors for toxicity to kill life). https://github.com/kiwijuice56/sand-slide/blob/main/extension/elements/chemical/acid_gas.h , https://github.com/kiwijuice56/sand-slide/blob/main/extension/sand_simulation.cpp
  - Generic `liquid_process(fluidity)`: random lateral step with slight bias (0.5+1/32), fall if possible, 60% move chance. Same file.
- **Powdered World Engine** — CannedBottle, Godot Asset Store, **MIT**, v1.0 changelog 2026-10-07, updated 2026-10-22; **Godot 4.7 C#/.NET only** (so **no web export** for C# in Godot 4 — inference from known C# web limitation, not stated on page). Default elements include **Acid**, Water, Fire, Smoke, Stone; no-code reaction editor; chunked sim with dirty rects. https://store.godotengine.org/asset/cannedbottle/powdered-world-engine/
- **SoftBody2D** (appsinacup), MIT, Asset Library id 1621, Godot 4.4 listing; RigidBody2D + Joint2D + Skeleton2D deformation; supports breakable bodies and holes (slime splitting candidate). https://godotengine.org/asset-library/asset/edit/11195 , https://appsinacup.itch.io/godot-softbody2d
- **Nojoule "Pixel UI VFX" / "Pixel Art Shaders"** (itch, devlogs incl. "Dissolve Effect", "Iterative Fire v1.4.0"): paid packs; devlog page failed to load. https://nojoule.itch.io/pixel-ui-vfx , https://nojoule.itch.io/pixel-art-shaders/devlog/1108781/dissolve-effect-and-improvements

### Inferences
- Top-down port of Sand Slide acid: replace "down" with "downhill on tile height" (or random 4-neighbor walk with no gravity); keep EAT×(1−resistance) as the universal corrosion rule → a material table (wood 0.2, leather 0.3, iron 0.5, stone 0.7, bone 0.6, gold/glass 0.95–1.0) is a natural fit (values are my proposal, not cited).
- Combine: CPU tile CA (Sand Slide rules, gameplay truth) + GPU DrawableTexture2D wet map (ProfesorShader, visuals) → cheap, web-safe.
- SoftBody2D is likely overkill for pixel slimes (joints + skeleton cost, non-pixel deformation); metaball threshold in a CanvasGroup is cheaper and more on-style (inference).

### Gaps
- GitHub API blocked → no stars/last-push dates for sand-slide, GodotFallingSand, godot-metaball.
- No itch.io acid-specific VFX pack verified with licence in window.
