# Figure plan for vfx-fog (shared by two figure agents)

The study has two equal goals: ARTISTIC QUALITY and RUNTIME EFFICIENCY. Every figure must look good as pixel art AND, wherever the technique has a cost, show a live cost readout (measured ms with performance.now() in the demo, or the report's measured figure from §6a, labelled which is which). Comparison figures put the pretty-but-expensive and cheap-but-ugly options side by side.

Figure names are FIXED. Each `<!--FIG name-->…<!--/FIG-->` block lives in the file listed, its demo is registered with `reg('name', …)` in the matching demos file. Markup follows studies/vfx-water/figs*.html exactly (`<figure class="fig" data-demo="name" id="fig-name">`, `.fig-h` with `Fig. @N`, title, `.illu` label when numbers are illustrative, canvases, controls, figcaption). Figures use only facts in studies/vfx-fog/report.md; label illustrative numbers. No images, no game art: original abstract pixel drawings in code. Animations via the core.js demo runner (requestAnimationFrame, paused offscreen). Dither patterns are locked to the figure's world pixels. Every figure must work at 390 px phone width without horizontal overflow and with zero console errors.

The recipe is studies/vfx-water/build.py (the newest, same report layout). The scaffolded studies/vfx-fog/build.py was cloned from vfx-light and is stale: Agent R rebuilds it from the water recipe.

## Agent R (recipe owner): build.py, hero.html, core.js, style.css, study.css, figs1.html + demos1.js, figs3.html + demos3.js
figs1.html / demos1.js
- `hero` (in hero.html; demo in demos1.js): live small highland scene with valley fog pooling in low ground, lamps glowing in the fog, cloud shadows; buttons "Valley fog", "Cloud shadows", "Fog of war", "Night mist"; a small live ms readout.
- `timeline`: the §3 generations, clickable.
- `emerald` (A1): Pokémon Emerald style fog: world-locked 64x64 tiles, fixed blend (12/16 + 8/16), drift ~15 px/s horizontal or diagonal 20x12; fade in/out.
- `alttp` (A2): ALttP overlay: a layer averaged 50/50, drifting 7.5 px/s and ignoring the camera vs following at 1/2 or 1/4 speed; pan the camera to feel the difference.
- `rtsfog` (A5): shroud / fog / visible states (Stratagus opacities 100/75/50%), StarCraft-style 32 px vision tiles, full rebuild every N frames vs instant reveal on tile entry.
- `noiselayers` (B1): 1-3 noise-table layers at different speeds and directions vs procedural fbm (1-4 octaves); live ms for each; the drift-speed slider marks the "reads as smoke" zone.
- `warp` (B2): domain warp as a texture offset (2 fetches) vs nested fbm; side by side with costs.
- `pooling` (B3): height map cross-section and top view; fog line slider; Beer's law transmittance exp(-k*thickness); fog fills valleys and leaves ridges clear; clears from the edges inward as the line drops.
- `density` (B4): coarse density grid with wind advection and diffusion at a low update rate vs every frame, interpolated; ms readout; wind slider.
- `clearing` (B5): fog parting around a walker and lamps via a clearing mask; radius sliders.
- `dither` (C1): world-locked Bayer 4x4 vs screen-locked (swims when the camera pans) vs blue noise vs temporal; camera pan toggle.
- `paletteLUT` (C2/C3): palette value compression LUT vs plain alpha: show the off-palette colour count each one produces, live.
figs3.html / demos3.js
- `costs` (6a): the measured cost table as a log-scale bar chart (GPU 320x180 / 720p, CPU JS normal and 6x throttled) with the 16.7 ms frame line; toggles for resolution and throttle; source labels.
- `matrix` (6b): the pretty-vs-cheap matrix as an interactive scatter: each technique by Speed vs Pixel taste + Mood from the §5 ratings; hover/click shows the profile.
- `score`: the §5 scorecard, sortable, with a radar for the selected row (copy vfx-water's score figure pattern).
- `stack` is generated by build.py from §7 (9 layers).

## Agent F: figs2.html + demos2.js only (never edit build.py, core.js, hero.html, figs1/3, demos1/3, style.css, study.css)
- `cloudshapes` (D1): thresholded scrolling noise table; cloud cover slider; edge band; world-locked so shapes don't swim.
- `cloudshadow` (D2): palette-step shadow vs multiply shadow over a pixel scene (count off-palette colours); sun offset; wind drift.
- `overhead` (D3): parallax overhead clouds drifting faster than the shadows, dithered fade near the player/camera centre.
- `fowcounts` (E1/E2): fog of war on a grid with several moving units: visibility counts and explored bit; full recompute vs full re-stamp vs delta (enter/leave cells) with live ms and touched-cell counts; unit count slider (10-1000).
- `fowedges` (E3): hard cells vs 16-case edge tiles vs bilinear upscale + blur vs dithered threshold; zoomable.
- `remember` (E4): reveal fade-in (~0.3 s) and remembered tiles (darker desaturated palette, DCSS-style mesh, Brogue-style blue tint) vs unknown.
- `servervision` (E5): MMO server-side vision: what the server sends to each client (entities inside vision only), a "maphack" toggle showing that hidden entities are never in the packet; bytes per tick.
- `haze` (F1): haze by height/distance: hue-only tint vs tint plus contrast drop; strength slider.
- `halos` (F2): additive halo sprites sized by local fog density vs PointLight2D-style per-pixel lights; lamp count slider with cost.
- `shafts` (F3/F4): pre-drawn light shafts vs radial-blur god rays with a sample-count slider (8-64) and live ms; dust motes toggle (F5).
- `smoke` (G1): cast fog-cloud spells/smoke bombs on a grid: density decays; cells above a threshold block sight for a walker's FOV.
- `weather` (G2/G3): weather state machine per region (one byte), radiation fog timing over a compressed day (forms at night in low moist ground, deepest at sunrise, burns off from the edges); bytes sent.
- `fogcolour` (H1): fog colour follows time of day; desaturated sky hue; scrub the clock.
- `readable` (H2/H3): characters above the fog vs inside it vs fog behind them; strength slider and reduce-motion toggle.
